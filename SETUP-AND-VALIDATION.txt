DATABASE CHANGES
The migration adds account/branch activation, session revocation, audit and stock movement tables, request idempotency, import hashes, catalogue functions/indexes and order stock-commit tracking. Product images support unique EAN plus image type, allowing front/back/side/detail views. Wholesale items have separate product references and name snapshots.

Apply via npm run migrate, which commits enum additions before the main migration transaction. Re-running is supported. Existing business records are retained. Legacy reserved quantities are not blindly reset: reconcile them with actual stock and open orders.

STAFF ACCESS AND INVENTORY
Branch admins can work only with their assigned branch's retail stock, sales, product entry, imports, POS and movements. The API enforces this restriction. Superadmin can select any branch or all branches, manage branches/admins, shared prices, categories, customers, homepage media, shipping, rewards, wholesale operations and audit records.

Shared catalogue prices apply across branches; changes to existing shared prices require superadmin. Stock adjustments use the selected branch and reject stale updates. POS scanning is read-only; confirmed sales deduct stock atomically, and retrying the same confirmation does not deduct twice. Normal staff pages use light backgrounds, with black navigation and mobile layouts.

MANUAL PRODUCT ENTRY
Choose branch -> department -> category/subcategory. Enter name, source brand, style code, fit, colour, size, unique EAN, prices, pack size and opening quantity. Repeat with the same style fields for additional colours/sizes and a different EAN. Quantity means selling units/packs, not individual pieces inside a pack. Prices are per selling unit. A positive discount percentage takes priority over selling price; otherwise selling price, then MRP, is used.

EXCEL REFERENCE
Use Tara-Product-Import-Template.xlsx. Products is the first sheet; Instructions is the second. Replace/remove the four DEMO rows before uploading actual stock. One row represents one colour and size. Keep EANCode as TEXT to preserve leading zeroes.

Exact columns:
ProductName, BrandName, PATTERN, FITT, SIZE, COLOUR, EANCode, MRP, RSalePrice, CostPrice, B2CDiscount, B2BDiscount, PurchaseQty, PackSize.

Select branch, department and category before uploading. One file belongs to that selected branch/category. Upload XLSX/CSV, review validation errors and process the job. Limits: 10 MB, 20,000 rows, batched processing. Re-uploading the identical file for the same branch/category resumes/reuses its original job and does not duplicate stock. A new receipt needs a distinct receipt file.

The prefix must match the EAN exactly. JPG/JPEG/PNG/WebP are supported. Shared product/colour/fit naming is also explained in the page. Configure Cloudinary server credentials or supported Blob storage. Uploads go through the authenticated backend; no private upload credentials belong in React.

CHECKOUT, PAYMENTS AND SHIPPING
Retail checkout derives totals from the database, ignores client payment flags/prices and chooses one active branch able to fulfil the complete basket. WEB_BRANCH_ID optionally fixes online fulfilment to one branch. A basket that cannot be fulfilled by one branch is rejected with an availability message.

Stock is committed when an order is created and is not deducted again for shipping. Pending online orders hold stock until paid or cancelled. Eligible unshipped customer cancellations restore committed stock and coins once. Real prepaid refunds still require provider processing and recording through the existing order-issues workflow; automatic provider refunds are not claimed.

Keep GIFT_WRAP_FEE=39 and DELIVERY_FEE=0 to match the current storefront. If changing commercial policy, update customer-facing cart amounts too.

Razorpay requires backend key ID, key secret and webhook secret. Verification checks signature, captured status, amount, currency and order reference. Signed webhook endpoint: /api/razorpay/webhook. No live payment was made during development.

Shiprocket requires SHIPROCKET_API_USER_EMAIL, SHIPROCKET_API_USER_PASSWORD and SHIPROCKET_WEBHOOK_TOKEN. In superadmin Shipping map each branch to its real pickup ID and exact pickup name. Configure the webhook's x-api-key to match your token. Real courier allocation, labels and tracking require testing with your account.

Wholesale retains the existing shared b2b_products warehouse, separate from retail branch stock. A preferred branch is a fulfilment request, not branch-specific wholesale availability. The repaired wholesale checkout validates identity/prices and records the correct wholesale product. Superadmin approval deducts warehouse stock once, then the manual workflow records received payment, dispatch and delivery. Ambiguous legacy wholesale product references require review before approval.
